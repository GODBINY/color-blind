## 1. Why — 이 프로젝트가 시작된 이유

빨간 장미가 활짝 핀 걸 봤을 때, 그 순간을 색약인 남자친구에게도 보여주고 싶었다.

하지만 그에게 빨강은 잘 보이지 않는다. 사진을 그대로 보내면 그 꽃은 배경 속에 묻혀버린다.

그래서 생각했다 — **그가 구분할 수 있는 색으로 바꿔서 보여주면, "아, 여기 꽃이 이런 느낌으로 예쁜 거구나" 하고 알 수 있지 않을까?**

이 프로젝트의 핵심은 색약을 "고치는" 것이 아니다. **내가 본 아름다움을, 그 사람의 색으로 번역해서 전하는 것**이다.

이 프로젝트의 가장 중요한 가치는 **공감(Empathy)** 이다.

## 2. Vision

> **Share the beauty you see — in colors they can see.**
>
> 내가 본 아름다움을, 그 사람이 볼 수 있는 색으로.

## 3. 제품의 두 방향

| 방향 | 기능 | 역할 |
|---|---|---|
| **Show My View** — 내 아름다움을 그 사람에게 | Translate (색 번역/보정, daltonization) | **핵심 기능.** 색약인 사람이 구분하기 어려운 색을, 구분 가능한 색으로 리매핑해서 사진의 아름다움(꽃이 도드라지는 느낌, 색의 대비)을 전달 |
| **See Their View** — 그 사람의 세상을 나에게 | Simulate (색약 시야 시뮬레이션) | 보조 기능. 보내는 사람이 "왜 번역이 필요한지" 이해하게 하고, 번역 전/후를 그 사람의 시야로 검증 |

두 기능은 같은 기술 파이프라인을 공유한다 (번역 = 시뮬레이션 + 오차 재분배, [04_Tech.md](04_Tech.md)).

## 4. Target Users

### Primary
| 사용자 | 핵심 니즈 | 대표 시나리오 |
|---|---|---|
| **색약인 가족/연인/친구에게 아름다움을 전하고 싶은 사람** | "이게 얼마나 예쁜지 보여주고 싶다" | 장미 사진을 남자친구의 유형(Deutan)으로 번역해 공유한다 |
| **색약 당사자** | "남들이 보는 그 느낌을 알고 싶다" | 받은 번역 사진을 보거나, 직접 Live Camera 보정 필터로 꽃밭을 본다 |

### Secondary
- 자기 사진을 색약 시야로 변환해 보고 싶은 사람 (호기심, 공유)
- 디자이너 (접근성 검증 — 시뮬레이션 활용)
- 접근성에 관심 있는 개발자/PM, 교육자

## 5. Product Philosophy

### Core Values
1. **Empathy** — 이해가 먼저, 기능은 그다음
2. **Gift** — 이 서비스의 결과물은 "선물"이다. 검사 결과가 아니다
3. **Connection** — 번역된 사진은 공유될 때 완성된다
4. **Honesty** — 색각을 "고쳐준다"고 말하지 않는다. 우리는 번역할 뿐이다
5. **Simplicity & Beauty** — 사진 한 장이면 시작, 도구가 아니라 경험

### We are NOT
- 의료 서비스가 아니다
- 장애 진단·치료 서비스가 아니다
- 병원 느낌의 접근성 도구가 아니다
- "색약을 교정해주는" 서비스가 아니다 — 잃어버린 색 지각을 만들어낼 수는 없다. 색의 **구분과 인상**을 전달한다

### We ARE
- **서로의 시각 사이에서 아름다움을 번역하는 서비스**다

> 이 원칙은 카피 금지어 목록([08_Brand.md](08_Brand.md))과 Find My View 면책 문구([02_PRD.md](02_PRD.md))로 구체화된다.

## 6. 경쟁 서비스와 차별점

### 기존 서비스의 한계 (Color Blind Pal, Coblis 등)
- daltonization 기능이 있어도 공학 도구처럼 노출 ("필터 강도 파라미터 조절")
- 오래된 UI, 기능 나열식 UX, 웹 사용성 부족
- **"누군가에게 보여주기 위한" 흐름이 없다** — 결과 공유 경험 부재
- 감성적인 경험 부족 — 검사/보조도구 프레임

### 우리의 차별점
| 차별점 | 구현 방식 |
|---|---|
| **선물 중심 프레임** | "보정 필터 적용"이 아니라 "그 사람의 색으로 번역해서 보내기" ([08_Brand.md](08_Brand.md)) |
| 공감의 양방향 | 번역(Show) + 시뮬레이션(See)을 한 흐름에 |
| 현대적인 UX | Compare Slider, One Upload, No Learning ([03_UI_UX.md](03_UI_UX.md)) |
| 웹 우선 | 설치 없이 링크 하나로 받고 볼 수 있음 → 공유 바이럴 구조 |
| 검색(SEO) 중심 | Learn 콘텐츠 + 페이지별 키워드 전략 ([07_SEO.md](07_SEO.md)) |
| 프라이버시 | 모든 이미지 처리는 브라우저 내에서, 서버 업로드 없음 ([05_Architecture.md](05_Architecture.md)) |

## 7. MVP Scope

### 포함
- **Translate (Show My View)**: 업로드 → 상대 유형 선택 → 색 번역 → 미리보기("그 사람에게는 이렇게 보여요") → 다운로드/공유
- **Simulate (See Their View)**: 색약 시야 시뮬레이션 + Compare Slider
- **Live Camera**: 실시간 카메라 + 번역/시뮬레이션 필터 + 중앙 Color Picker (HEX/RGB/색 이름)
- **Find My View**: 유형 추정 Quick Check → 기본값 저장 (+ 상대에게 링크로 보내기)
- Learn (유형별 설명 3종 + FAQ)
- LocalStorage 개인화 (visionType, severity, language)
- Responsive Web (모바일 우선), English / Korean

### 명시적 제외 (MVP에서 하지 않는 것)
자세한 사유는 [09_Roadmap.md](09_Roadmap.md) 참고.
- 회원가입/로그인, 서버·DB, 이미지 서버 저장
- 번역 사진을 URL로 호스팅해서 공유 (MVP는 이미지 파일 자체를 공유)
- GIF/비디오 번역, AI 장면 설명
- PWA 오프라인, 다국어 3개 이상

## 8. 성공 지표 (MVP 기준)

| 지표 | 목표 | 측정 |
|---|---|---|
| 첫 방문 → 번역 실행 전환율 | 40%+ | GA4 퍼널 |
| 번역 → 다운로드/공유 전환율 | 20%+ (핵심 지표 — "선물"이 실제로 전달되는가) | GA4 이벤트 |
| Find My View 완료율 | 60%+ (시작 대비) | GA4 퍼널 |
| 오가닉 검색 유입 | 런칭 3개월 후 주간 500 세션 | Search Console |
